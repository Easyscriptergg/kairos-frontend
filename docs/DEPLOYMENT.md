# Deploying Kairos

Two repositories, two hosts:

| Repository | What | Host |
|---|---|---|
| `kairos-frontend` (this folder) | React + Vite app | Vercel |
| `kairos-backend` (Spring Tools workspace) | Spring Boot API + PostgreSQL | Render |

**Status:** both projects build, and every test suite passes locally. Neither has a GitHub remote, and neither is deployed: that needs your own GitHub, Render and Vercel logins. The steps below are written for you to do once, in this order. They do not require pasting a secret anywhere, including into chat.

## Before you start: decide on cost

Render's free tier is enough to try the app, but **not to keep real data**. Per [Render's free-tier documentation](https://render.com/docs/free), checked on 14 Oct 2026:

- A **free web service** spins down after 15 minutes without traffic. The next request takes about a minute while it wakes; the app waits up to 70 seconds before reporting an error.
- A **free PostgreSQL database** has 1 GB of storage and **expires 30 days after creation**. You then have 14 days to upgrade it to a paid plan, after which **Render deletes the database and all its data**.

`render.yaml` uses the free plans. To keep data beyond 30 days, upgrade the database to a paid plan in the Render dashboard before it expires; check [render.com/pricing](https://render.com/pricing) for current prices. Nothing in this repository will create a paid resource by itself.

Vercel's Hobby plan is free but, per Vercel's terms, intended for personal, non-commercial use. Check [vercel.com/pricing](https://vercel.com/pricing) if Kairos will be used commercially.

## 2. Deploy the backend on Render

1. Render dashboard → **New** → **Blueprint** → connect GitHub and select `kairos-backend`.
2. Render reads `render.yaml` and shows two resources: `kairos-db` (PostgreSQL 17) and `kairos-backend` (Docker web service), both on the **Free** plan. Confirm the plans are Free unless you have decided to pay.
3. It asks for `KAIROS_CORS_ORIGINS`. Leave it as `http://localhost:5173` for now; you will set the Vercel URL in step 4. `KAIROS_JWT_SECRET` is generated by Render automatically.
4. Click **Apply**. The first build takes several minutes (Maven downloads dependencies inside Docker).
5. When the service is live, open `https://<service-name>.onrender.com/health`. It must return `{"status":"UP","database":"UP"}`.

Copy the service URL; the frontend needs it.

## 3. Deploy the frontend on Vercel

1. Vercel dashboard → **Add New… → Project** → import `kairos-frontend`.
2. **Root Directory:** leave as the repository root, which is where `package.json` is. Vercel detects **Vite**; `vercel.json` sets the build command (`npm run build`), the output directory (`dist`), and the rewrite that makes refreshing any route work.
3. **Environment Variables:** add `VITE_API_BASE_URL` = `https://<service-name>.onrender.com/api` (with `/api`, without a trailing slash) for **Production** and **Preview**.
4. **Deploy.** Note the production URL, for example `https://kairos-frontend.vercel.app`.

## 4. Connect them

1. Render → `kairos-backend` → **Environment** → set `KAIROS_CORS_ORIGINS` to the Vercel production URL, without a trailing slash. To allow preview deployments too, list each preview URL separately, comma-separated; wildcards are not supported.
2. Save; Render redeploys automatically.

## 5. Verify production

In a private browser window, open the Vercel URL and check:

- [ ] The sign-in screen appears.
- [ ] **Create account** works, and you land on an empty Overview.
- [ ] Log a session, a recovery check-in and a meal; each appears.
- [ ] Refresh the page: everything is still there.
- [ ] Open `/train` directly in a new tab: the page loads (SPA rewrite).
- [ ] Sign out, then sign in again: the data is back.
- [ ] Create a second account: it sees none of the first account's data.
- [ ] In DevTools → Network, requests go to `onrender.com`; none go to `localhost`.
- [ ] DevTools → Console shows no errors other than expected 401s after signing out.
- [ ] Render → `kairos-backend` → **Manual Deploy → Restart service**, then refresh: the data is still there.

If sign-in fails with "Could not reach the Kairos API", the service may still be waking up (wait a minute and retry), `VITE_API_BASE_URL` may be wrong (redeploy Vercel after fixing it), or CORS may not list the exact Vercel URL.
